# Documentation Principles

## Core Principles

- Write from implemented behavior, not planned behavior.
- Keep terms consistent: Product, WorkItem, Relationship, Signal, KPI, Decision.
- Prefer structured sections and explicit fields over prose-heavy pages.
- Keep each file single-purpose and link related artefacts.
- Record assumptions and unknowns directly.

## Machine-Friendly Guidance

- Use stable headings across files.
- Keep list labels consistent.
- Prefer explicit values (status, owner, cadence, thresholds).
- Link WorkItems, Signals, KPIs, and Decisions by name.

## Quality Bar

A document is complete when:

- Scope is clear.
- Mappings to Product OS concepts are explicit.
- Measurable outcomes or KPIs are present when relevant.
- Follow-up WorkItems are identified for open actions.
